## Deviations / notes

- PowerShell blocked `npx.ps1`, so every npm command was run as `npx.cmd` with the
  same arguments (the plan's Global Constraints allow this).
- `duplicate_layer` re-finds the copied layer by id before reshaping it. The plan
  says to read the id before the insert; `duplicate_tucked` can insert a sound copy
  earlier in the list, so the old `layers[idx + 1]` index is no longer guaranteed to
  be the copy.
- `follow_range`'s trim clamps the sound's start to `end − MIN_SPAN_MS` in the
  degenerate case where a head trim would push it past the comp (the Task 2 test
  `a_trim_never_leaves_the_sound_shorter_than_the_minimum_or_outside_the_comp`
  covers this); every other limit is as listed in the plan.
- A move drag uses a per-sound clamp on 0 / comp end in the backend; the frontend
  also widens the group bounds so the pair stops together.
- Manual checks in Tasks 6 and 7 are reported as **not run**, and their plan
  checkboxes are left unticked.
